## Framework Overview

Please build a professional, maintainable Playwright test automation framework with the following project structure:

```text
project-root/
├── tests/
├── specs/          # All .spec.ts test cases
├── pages/          # Page Object Model classes
├── utils/          # Reusable helper functions
├── fixtures/       # Shared/custom Playwright fixtures
├── testdata/       # JSON, CSV, and other test data
│
├── playwright.config.ts
├── tsconfig.json
├── package.json
└── README.md
```

**Important:**

* All folders above must be created at the **same project-root level**.
* Use Page Object Model with `pages/`.
* Keep reusable helpers in `utils/`.
* Keep shared Playwright fixtures in `fixtures/`.
* Keep test data in `testdata/`.
* Do not put the entire test implementation into a single `.spec.ts` file.
* Keep `tests/` available for other general test-related files if needed.

The framework should also:

1. Handle test failures gracefully with screenshots and logs.
2. Use reliable Playwright locator strategies.
3. Support Chromium
4. Support parallel test execution.
5. Be easy to maintain and update.
6. Provide clear error messages when tests fail.
7. Use Playwright best practices and TypeScript.

## How to Describe Page Elements

When I need to interact with something on the page, I'll describe it in multiple ways:

1. By its visible text

* The exact text shown on the button/link
* Any nearby text that helps identify it
* The label or placeholder text

2. By its purpose

* What the element does (submit form, search, etc.)
* What kind of element it is (button, textbox, dropdown)
* Where you would expect to find it on the page

3. By its appearance

* What it looks like (color, size, icon)
* Where it appears on the page (top, bottom, near other elements)
* Any special styling or state (disabled, highlighted)

4. By its context

* What section of the page it's in
* What comes before or after it
* What it's related to
